# Run the five-market catalog workflow locally

Use Node 24.8+ and Python 3.11+. These commands read and write a private folder on your device. They work without package installation, credentials or hosting. Start at the repository root.

    npm run catalog -- demo /tmp/yawmiyati-demo
    npm run catalog -- review /tmp/yawmiyati-demo
    npm run catalog -- research /tmp/yawmiyati-demo
    npm run catalog -- approve /tmp/yawmiyati-demo sa DEMO-R3 <revision-from-review>
    npm run catalog -- draft /tmp/yawmiyati-demo sa DEMO-R3 <same-revision>

Open the resulting HTML on your device. The matching JSON contains the editorial fields and sources. Undo a decision with the same arguments using `revoke`. Re-run review after changing evidence or costs. SQLite records local decisions by market, SKU and revision, including revocations. It is a single-operator workspace. Treat drafts already exported as snapshots. Keep private inputs, media and the SQLite file outside the repo. A new assessment checks current evidence using the machine clock. The fictional dataset deliberately replays a fixed timestamp.

## Bring in a saved Woo catalog

Put a `woo-pages.json` file in a fresh folder and run `npm run catalog -- woo <folder>`. The command creates a new private `catalog.json` and refuses to overwrite one. Include each available market under its lowercase code. Copy the page totals from the Woo response headers for each captured product page. Observe the Woo source timestamp used by candidate review if you want to load the draft in the authenticated dashboard later.

    {
      "sa": {
        "observedAt": "2026-11-21T12:00:00Z",
        "pages": [
          {"page":1,"totalPages":1,"totalProducts":1,"products":[
            {"id":10,"sku":"RACK","name":"رف مطبخ","categories":[{"name":"مطبخ"}],"variations":[]}
          ]}
        ]
      }
    }

Each variation starts as a separate unresolved record. A generated woo- identifier is an intake reference only. Set the verified supplier offer SKU, composition, model, pack identity and orderability from evidence before shortlisting it. Woo coverage only counts the supplied Woo catalog. Check Taager catalog counts separately when its adapter is available.

## Collect and attach market evidence

The research command creates local price and search-interest queries for each offer. Set `productKey` to the exact model, variant and pack identity used for comparisons. Save observations under `<folder>/evidence/` using a separate JSON file for each observation. The program automatically loads them by market and product key.

Capture price from a saved retailer page with the exact retailer SKU, MPN or GTIN. Use the SKU corresponding to the verified pack. Shipping is in major currency units. Omit it when unknown. A missing shipping charge holds the comparison. The optional `--fetch` switch reads the one supplied public retailer URL instead of a saved page.

    python3 scripts/catalog/capture-price.py --page retailer.html --url <retailer-url> --market om --id-field gtin13 --identity <exact-gtin> --product-key <matched-pack> --observed <ISO-capture-time> --shipping 1.500 > <folder>/evidence/shop.json

For demand, export a weekly interest-over-time CSV from Google Trends with the product term and a common local benchmark together. Use the same benchmark and period across products you intend to compare. Include the exact two column names and country-specific Trends URL.

    python3 scripts/catalog/trends-csv.py --file trends.csv --url <trends-url> --market om --term '<product column>' --anchor '<benchmark column>' --product-key <matched-pack> --observed <ISO-capture-time> > <folder>/evidence/interest.json

The result is an interest score relative to the chosen benchmark. It measures search interest. Retail sales volumes require separate evidence. Record the other research factors with a dated source URL and verified score. The example generated by `demo` shows the input format. The planner holds missing or stale evidence. Pages without suitable structured product data need a sourced manual comparison.

## Economics, content and approvals

All stored amounts are integers in the local currency's minor units. Fill the product cost, outbound shipping, delivered fees, unrecovered return cost, per-order acquisition cost, and estimated delivery probability in basis points. Include shipping/tax/COD costs only once. The calculator conservatively excludes shopper shipping income from seller contribution. Choose a proposed price, or set `targetContributionMinor` and leave price null to calculate the lowest viable price above the floor and below the comparable delivered total. Review output shows each family winner, the score, expected contribution, benchmark and blockers. Set `YAWMIYATI_FAMILY_LIMIT` to change the per-market maximum (1–150).

Supply approved local Arabic facts as `{id,text,source}`. The title fact must match the offer title. FAQs reference fact IDs. Supply local approved PNG/JPEG artwork under `media/` and add `{file,checksum,alt,factId,rights}`. The checksum is the raw file's SHA-256 hex digest. A changed image requires updated evidence and a fresh approval. Exported HTML embeds permitted images so the draft can be reviewed offline. Unknown dimensions, materials, delivery promises and performance claims require new facts before they can appear.

The authenticated owner dashboard can load the JSON title and description through **Content and catalog draft → Load offline editorial draft** for an exact non-demo, parent Woo candidate. It compares market, supplier SKU, Woo ID and observation timestamp. The owner must still approve the content in their account. Offline SQLite decisions do not grant server approval. Variations remain available for offline review until the server candidate contract supports them.

Run the end-to-end local checks with `node --test scripts/catalog/prehost.test.mjs`. Live Taager fields, commercial terms, source coverage, stock freshness, delivery zones and actual order/status behavior must be verified after connection.

## Review a whole shortlist

Run `npm run catalog -- board <folder>` and open `catalog-review.html`. Select the offers you want, then download the selection file. Claude or the local operator can record those exact decisions in one transaction using `npm run catalog -- batch-approve <folder> <selection-file>` and generate their drafts with `npm run catalog -- batch-draft <folder> <selection-file>`. Both commands re-evaluate the snapshot and reject superseded revisions. Each draft has its own revision-specific filename so interrupted batch exports can be rerun.

## Account-backed pack and price decisions

The review command includes an `accountProposal` for each selected offer. Once the source migration `20261121210000_offline_offer_decisions.sql` has had an authorized rollout, paste a non-demo proposal into **Owner dashboard → Account offer decisions**. Review the exact pack, price and expected contribution, then approve. Sign into the same owner account on another device, select the same country and find the SKU to read or revoke the decision. History is private to the account and country. A stale edit requires a reload. This record approves an assortment proposal only. Customer publication and order routing use their existing separate workflows.
